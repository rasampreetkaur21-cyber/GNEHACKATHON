# Master brief

This brief reflects the supplied build prompt, not an external document. Build a secure warranty investigation foundation from an empty workspace using React 18/Vite/Tailwind/Router, Express, better-sqlite3, Zod, Vitest and Supertest.

Customers register/login, create persisted UUID claims, upload private evidence, and track status and activity. Reviewers inspect all claims, rule explanations and attachments, request clarification and make final decisions. No automated misconduct accusation or final decision.

Required tables: users, claims, evidence, investigations, rule_results, audit_events, warranty_policies, serial_registry, datasets_provenance. Additional sessions and repair_context support authentication and aggregate imports. Repeatable initialization preserves existing data and enforces foreign keys.

Only independently verified policies and registry records establish eligibility. Missing evidence means uncertainty. R01–R05 produce traceable PASS/FAIL/UNKNOWN results and advisory AUTO_APPROVE/ESCALATE/NEEDS_EVIDENCE/REJECT_RECOMMENDED outcomes.

Forty visibly synthetic cases span four products and eight scenarios with a fixed seed and independent expected outcomes. ORA imports retain attribution, license, checksums and status; aggregate repair context never proves individual service history. Claude configuration is server-only, with no fabricated observations. Phase 2 adds server-only Claude Vision and invoice image OCR, secure decoded images, EXTRACTED/ASSERTED/VERIFIED trust, persistent call budgets and truthful unavailable states. Chatbot, Judge Challenge Mode and Decision Twin remain outside scope. See PHASE2.md and PHASE2_VERIFICATION.md.

## Phase 3 current scope

The Phase 3 prompt supersedes the initial five-rule registry with R01–R10, engine 3.0/rule definitions 1.0. Historical results and evaluator remain version 0.1. Exact priority is anchored-expiry advisory rejection without material contradictions, then essential/major escalation, then missing essential evidence, then fully gated automatic recommendation, then escalation. No approval threshold was supplied; actual company policy configuration must provide it. No real seller/registry/service data is invented.

Reconciliation, top-three next evidence, immutable ledgers, private reviewer notes/linkage, and the eleven-state persistent guided assistant are implemented. The assistant uses the same claims, uploads, analysis budgets and rules as the ordinary form. It collects private draft evidence, requires explicit confirmation/submission, and returns the actual UUID. LIMITED MODE is functional without Claude. Judge Challenge Mode and Decision Twin remain out of scope. Current contracts/limits: PHASE3.md; executed checks: PHASE3_VERIFICATION.md.
